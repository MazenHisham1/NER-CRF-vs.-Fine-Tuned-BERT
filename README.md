# Named Entity Recognition on CoNLL-2003: CRF vs. Fine-Tuned BERT

A side-by-side comparison of a classical feature-based model (Conditional Random Field) and a fine-tuned transformer (`bert-base-cased`) for named entity recognition, evaluated with strict entity-level metrics, followed by error analysis and a packaged inference function.

## Overview

| | |
|---|---|
| **Task** | Token classification (NER) with `PER`, `ORG`, `LOC`, `MISC` |
| **Dataset** | [CoNLL-2003](https://huggingface.co/datasets/eriktks/conll2003) (14,041 train / 3,250 validation / 3,453 test sentences) |
| **Models** | CRF (`sklearn-crfsuite`) and BERT (`bert-base-cased`, Hugging Face Transformers) |
| **Metric** | Entity-level precision, recall and F1 using `seqeval` (strict mode, IOB2) |
| **Tag scheme** | IOB2 |

> **Data:** CoNLL-2003 English NER (Tjong Kim Sang & De Meulder, 2003), built from the Reuters Corpus. The data is **not included in this repository**; the notebook downloads it at run time. The Reuters Corpus is subject to its own copyright and usage terms; see the [CoNLL-2003 page](https://www.clips.uantwerpen.be/conll2003/ner/) and the [Reuters Corpus page](https://trec.nist.gov/data/reuters/reuters.html).

## Approach

### 1. CRF baseline
Linear-chain CRF trained with L-BFGS (`c1=0.1`, `c2=0.1`, 100 iterations, all possible transitions). Features per token:
- lowercased word, 3-character prefix and suffix
- is upper / is title-case / is digit / contains hyphen
- the same case and word features for the previous and next token
- beginning-of-sentence and end-of-sentence markers

### 2. Fine-tuned BERT
`bert-base-cased` fine-tuned for token classification:
- the first sub-word of each word carries the label; other sub-words are ignored in the loss (`-100`)
- 3 epochs, learning rate 5e-5, batch size 16, weight decay 0.01, seed 42
- validation split is used for per-epoch evaluation only; the final epoch is used (no checkpoint selection on the test set)
- the test set is predicted once, after training

### 3. Evaluation
- Both models are scored on the same 3,453 test sentences with the same gold labels.
- Scores use `seqeval` strict mode with the IOB2 scheme, so only well-formed, exactly matching entities count.
- Overall, per-class and per-method reports are generated, along with token-level confusion matrices.

### 4. Error analysis
Each error is categorised as one of:
- **missed**: a gold entity with no overlapping prediction
- **wrong type**: correct span, wrong label
- **boundary**: correct label, wrong span
- **boundary + type**: overlapping span with both wrong
- **spurious**: a predicted entity that overlaps no gold entity

The notebook also lists sentences BERT fixed compared with CRF, and sentences where BERT is worse.

### 5. Packaged model and inference
After you run the pipeline, the fine-tuned model, tokenizer and a `run_config.json` (base model, hyperparameters, seed, label list, test metrics, library versions) are saved locally to `results/final_model/` (not committed to the repo). A small function turns raw text into entities with character offsets:

```python
tok, model = load_ner_model("results/final_model")
extract_entities("Barack Obama visited Cairo and met officials from the United Nations.", tok, model)
# [{'label': 'PER', 'start': 0, 'end': 12, 'text': 'Barack Obama'}, ...]
```

Each entity is returned as `{"text", "label", "start", "end"}`, where `start` and `end` are character offsets into the input (end exclusive).

## Getting started

```bash
pip install datasets seqeval sklearn-crfsuite transformers accelerate torch matplotlib numpy pandas
```

The notebook is written as a script with a `main()` entry point. To run the whole pipeline, export it and run it:

```bash
jupyter nbconvert --to script NER.ipynb
python NER.py --steps crf transformer --out-dir results --epochs 3
```

Options:

| Flag | Default | Description |
|---|---|---|
| `--steps` | `crf transformer` | Which models to train |
| `--out-dir` | `results` | Where outputs are written |
| `--hf-model` | `bert-base-cased` | Hugging Face model name |
| `--epochs` | `3` | Fine-tuning epochs |

A GPU is recommended for the BERT step.

## Limitations

- Evaluation is on the CoNLL-2003 test set only, which is English newswire; performance on other domains is not measured.
- The inference function splits text into words and punctuation with a simple regex, which is close to but not identical to CoNLL tokenization. Text longer than 512 sub-tokens is truncated.
- No hyperparameter search was run; settings are fixed defaults.

## Possible extensions

- Try larger or domain-specific encoders (RoBERTa, DeBERTa) and compare on the same split
- Tune hyperparameters on the validation set only
- Add a few-shot LLM baseline scored with the same strict metric
- Evaluate on out-of-domain data such as WNUT or OntoNotes
